# Smart Media Manager (Rajudesktop)

One Windows desktop program with three separate native tabs. Uses the existing tested processing engines, without changing or removing any of the original standalone apps.

**Tab 1 — Batch Video Clip Cutter (V2):** Add multiple PC videos in one batch and/or paste multiple YouTube URLs (one per line) into the same persistent FIFO queue. Each YouTube video downloads automatically then proceeds immediately to numbered MP4 clips; PC files go directly to cutting. Select adjustable length (default 4 seconds), optional keyword prefix, output root (Documents/ProcessedClips by default), quick presets, progress and per-job statuses. Every source has a separate output directory; no originals or existing clips are overwritten. Cancel preserves already completed clips; pending queue stays saved across app restarts; failed/cancelled jobs can be retried in new output directories without destroying previous partial output. YouTube downloads can fail if YouTube requires sign-in or blocks automated retrieval.

**Batch cutter video-only download and silent output:** The Smart Media Manager Clip Cutter now selects a **single video-only YouTube stream** (bestvideo/bv), never a separate bestaudio stream. It no longer requests FFmpeg video+audio merging. Its output clips are intentionally silent (no audio track), for both downloaded YouTube videos and local PC videos. A YouTube video with no accessible video-only format may fail rather than downloading a combined audio/video stream. Existing on-disk downloaded cache can still be reused, but cutting strips audio. The independent standalone Video Clip Cutter retains its previous audio behavior.

**Batch cutter quality and Fast Copy (November 2026):** New queue items default to **720p** and may select **1080p** using the **YouTube quality** dropdown beside Clip Seconds. This setting controls source stream preference *for YouTube downloads only*, with a fallback to other available video-only streams when needed. **Batch cutter outputs are now lossless-generation stream copies** of the selected source: video codec, original pixel dimensions and compressed video quality are retained without scaling or decoding/re-encoding. Local PC videos always keep their original resolution. Each queue record retains its selected YouTube quality, including jobs added during a running queue. Legacy queue records with no quality limit keep their original uncapped download preference. This mode does not guarantee exact target duration; cuts occur at suitable source keyframes. Standalone independent Video Clip Cutter remains on its original accurate transcoding engine.

**Batch cutter queue behavior (source-only change):** The cutter now has two independent lanes: one YouTube source downloads at a time, while one previously downloaded/local video is cut at a time. A completed download is handed to the cut lane immediately and the next download can begin without waiting for that cut to finish. New PC videos or YouTube links may be added to the queue while it runs; new items use the duration, keyword and output location set when added. The queue keeps its saved-state and cancellation behavior. The Smart Media Manager cutter runs a **single FFmpeg process per source**, using MP4 segment muxing and stream copy (no per-clip x264 re-encoding). **Every segment is checked with FFprobe**, including interior clips: any segment shorter than the requested minimum duration is discarded, and kept files are numbered sequentially without gaps. Keyframe alignment can make remaining clips longer than the requested target. A video with no qualifying segments yields zero clips. The independent standalone video cutter's original short-final-clip behavior is unchanged.

**Responsive Batch Cutter UI (November 2026):** The cutter controls now use a scrollable upper panel that shrinks on shorter Windows displays. PC/YouTube input cards and keyword/duration/preset/quality settings automatically rearrange into stacked rows as window width decreases. The output path and Browse/Open buttons reflow independently, the processing queue gets the remaining vertical space and its own horizontal/vertical scrollbars, and Start/Cancel/Retry/Remove controls wrap into multiple rows and stay pinned below the queue instead of being cut off at the bottom. Queue actions, media processing, saved preferences and the other app tabs are unchanged. The main window opens within the available screen dimensions and allows compact resizing. Windows CI exercises real Tk resizes at wide, medium and narrow desktop sizes before packaging the one-file EXE.

**Tab 2 — Image Renamer:** Choose a folder, include subfolders or add individual images. Keyword and start numbering, filename preview, copies by default to preserve input images, optional confirmed in-place rename with Undo, and remembered output location.

**Tab 3 — YouTube Downloader:** Full video, video-only and audio-only modes; multiple URLs, selectable quality/format, progress and saved retryable queue. The **Snapshots** subtab accepts multiple YouTube URLs (one per line), one selected local PC video, or multiple PC videos through **Add PC Videos**. Each snapshot job can have a custom name and saves its own output folder; interval, JPG/PNG format, image quality, resolution, start/end times and destination are frozen per job. Snapshot jobs run **one-by-one**, with **Add to Queue**, **Add & Start**, **Start Queue**, **Pause / Resume**, **Cancel Current** (then continue), **Stop Queue**, **Retry Failed**, **Remove Completed** and **Remove Selected** actions. Jobs can be added while processing without stopping the active item. No originals are changed.

## Snapshot queue, names and restart behavior

The snapshot queue persists separately from the regular YouTube Download queue at `%LOCALAPPDATA%\\SmartMediaManager\\snapshot_queue.json`. Active jobs are restored as **Queued** after a restart; Completed jobs remain in the history and failed/cancelled jobs can be manually retried. New items added during an active run join its FIFO pipeline. The **Queue** subtab remains for regular downloads; the snapshot queue is visible inside **Snapshots**.

Example: With snapshot name **Naomi Osaka**, each job writes to `<output>/Naomi Osaka [short-id]/`, with image files such as `Naomi Osaka 00001_00-00-00.jpg`, `Naomi Osaka 00002_00-00-05.jpg`. Each job uses an isolated output folder (including when two jobs have the same name), so no existing results are overwritten. Interrupted jobs reuse their own existing frames on retry. Snapshot source videos downloaded from YouTube are shared across repeated jobs for the same URL using the stable URL-hash cache at `<output>/.snapshot_cache/` and the Video Clip Cutter's `download_source()` implementation. All output folders and input file selections are local; YouTube links require platform access.

## YouTube snapshots share the Clip Cutter downloader

Snapshots now call the **same `smart_media_manager.cutter_queue.download_source()` engine** used by Batch Video Clip Cutter. There is no separate yt-dlp snapshot format selector or duplicate YouTube download logic. Both use the same MP4-first video-only format selection (without separate audio downloads or audio/video merging), FFmpeg configuration, resume behavior, and no-overwrite source caching. The downloader supports sources with no audio; FFmpeg extracts still frames from their video stream.

For queued snapshots, cached source videos are stored under the chosen output root's `.snapshot_cache/<stable-url-hash>/source.<ext>` directory. The existing direct-call snapshot API retains its original cache location. Completed frames and cached videos are reused on restart. Local PC video snapshots bypass YouTube entirely.

A format error may still occur if YouTube does not expose an accessible stream due to login, age restrictions, anti-bot rules, client changes, or outdated yt-dlp; the app then shows guidance to retry with a playable video or use **Choose Video from PC**. This cannot be guaranteed to work for every YouTube link.

## Windows download and run

From GitHub Releases download **SmartMediaManager.exe** directly from the latest **V3 Single Portable EXE** release. Save it anywhere (for example D:\\Apps\\SmartMediaManager.exe), then double-click. There is **no ZIP to extract and no adjacent support folder**. The single EXE embeds Python runtime, FFmpeg, FFprobe, yt-dlp and all three integrated tool modules. The PyInstaller one-file bootloader automatically extracts temporary internal components at runtime; user data and output clips are saved to the selected output folder and persistent settings/queue live under LOCALAPPDATA. The EXE is not an installer; it does not modify other apps. First launch may be slower because the EXE unpacks its embedded files.

Source run: `python launch_smart_media_manager.py`

Unit tests: `python -m unittest discover -s tests -p test_smart_media_manager.py -v`, `python -m unittest discover -s tests -p test_cutter_queue.py -v`, `python -m unittest discover -s tests -p test_snapshots_local.py -v`

All processing is local. Existing files are never overwritten automatically. Default image mode leaves originals intact. The standalone Smart Clip Renamer remains available independently. Existing Edge Voice, SML and desktop editor applications are independent and unchanged.
