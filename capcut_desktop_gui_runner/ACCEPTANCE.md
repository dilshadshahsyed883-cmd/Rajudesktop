# Acceptance before allowing another installed version

No shipped profile accepts CapCut 9.6.0.4097. Do not change the version gate solely to silence it.
On a disposable ready project and an unlocked Windows session, a developer must use the
original upstream tools directly for a supervised acceptance run: record installed executable
version, resolution/DPI, Home project identity, Export window/tree, each field and cloud-OFF
state, native folder picker, progress, actual completion and safe Close/Home controls.
Stop if cloud sync is ON; do not alter account/settings in this workflow. Never activate Pro.

Record original JSON hashes before/after, expected output settings, full video/audio decode,
codec/duration/resolution/audio result, output hash and visual/listening checks. Re-run with
at least two projects sequentially and test unexpected dialogs/partial outputs/no overwrite.
Only then propose a version-qualified gate change with evidence and regression checks.
No current Windows GUI test or overnight reliability certificate exists in this package.

Upstream source remains available for this controlled audit; the launcher's refusal does not
prove the newer version is incompatible, only that it is unaccepted.
